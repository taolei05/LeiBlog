| P2 | 后台深层路由刷新可能返回前台入口，静态 HTML 缺少独立安全策略 | Caddy 分别回退至 `/index.html` 和 `/admin/index.html`；HTML 禁缓存，hash 资源长期缓存，配置 CSP、防嵌入、HSTS、no-sniff；上传保留 API sandbox 策略 |
| P2 | PostgreSQL 正常 NOTICE 充斥每次启动日志 | 抑制 NOTICE，保留失败异常和启动状态；容器日志按大小轮换 |

## 仍需上线前确认

1. **必须先将完整新代码推送到部署分支**，包括当前未跟踪的新文件。此工作区已有大量历史改动，本次没有替你提交、推送。旧项目数据库/卷不支持直接原地切换，需要单独规划迁移。
2. 在真实服务器检查域名 A/AAAA、80/443、防火墙、证书签发与续期、磁盘/备份容量。已有反向代理占用端口时不能直接套用默认栈。
3. 按实际域名配置并验收 Resend/SPF/DKIM、OAuth 回调、R2/DeepL 等外部服务；本地测试不发送真实邮件，也不代表公网链路已经可用。
4. 若在 Cloudflare/CDN 后部署，配置精确可信 CDN 网段及严格代理链。默认未信任 CDN 头时只能看到 CDN 节点 IP；不要为方便而信任所有私网或任意来源的 IP 头。
5. 手动浏览器验收登录、ALTCHA、注册/发送验证码、评论、上传/预览、OAuth 回跳和中英文页面。遵循项目偏好，没有自动操作浏览器；HTTP 和组件测试不能替代这一项。
6. R2 对象独立备份，部署归档含个人资料和加密密钥，需加密异地保存；恢复历史数据库后检查通知队列，避免重发旧邮件。保留经过验证的更新前备份再发布。

## 后续维护

当前幂等 schema 仍在每次启动执行，下一阶段可以迁移为按版本记录的增量迁移。共享 API、文章编辑/内容管理等文件仍较大，适合在上线稳定后按资源拆分；编辑器和部分语法/Emoji 依赖仍带来大分块警告，需要结合实际首屏性能继续优化。日志、磁盘、邮件失败和备份可恢复性应加入实际运行监控。
