# 评论邮件通知功能设计

**日期：** 2026-06-12
**状态：** 已确认

## 目标

为 LeiBlog 增加评论邮件通知功能：

- 任意登录用户在文章或留言板发布评论、回复后，通知所有符合条件的管理员。
- 普通用户的评论收到直接回复后，通知该评论作者。
- 管理员和普通用户均可在个人偏好设置中控制是否接收评论邮件通知。
- 邮件发送失败不影响评论正常发布。

## 范围

本功能包括：

- 用户级评论邮件通知开关，管理员和普通用户默认开启。
- 管理员新评论、新回复邮件通知。
- 用户评论收到直接回复时的邮件通知。
- 后台“管理员设置”中的评论邮件通知开关。
- 前台个人中心新增“偏好设置”及评论回复邮件通知开关。
- 复用现有 LeiBlog 邮件模板视觉样式。

本功能不包括：

- 未登录访客评论通知。
- 向回复者本人发送自我回复通知。
- 向同一评论线程中的所有参与者发送通知。
- 邮件失败重试队列、发送历史和后台发送记录。
- 单独的站点级全局评论通知开关。

## 数据模型

在 `users` 表增加字段：

| 字段 | 类型与约束 | 用途 |
| --- | --- | --- |
| `comment_email_notifications_enabled` | `boolean NOT NULL DEFAULT true` | 控制当前用户是否接收评论相关邮件 |

管理员和普通用户共用该字段：

- 管理员开启时，可接收全站文章和留言板的新评论、新回复通知。
- 普通用户开启时，可接收自己评论被直接回复的通知。
- 已有用户在迁移后默认开启。
- 没有有效邮箱的用户即使开启开关，也不会成为邮件收件人。

当前仅有一个个人偏好项，因此直接在 `users` 表增加字段，不新增独立用户偏好表。

## 个人偏好接口

扩展当前用户资料响应，返回：

```json
{
  "commentEmailNotificationsEnabled": true
}
```

新增当前用户偏好更新接口：

```http
PATCH /api/me/preferences
Content-Type: application/json

{
  "commentEmailNotificationsEnabled": false
}
```

接口要求当前用户已登录，只允许修改自己的偏好。服务端校验字段必须为布尔值，保存后返回更新后的偏好。

## 收件人规则

### 管理员通知

每次文章或留言板评论、回复成功创建后，筛选全部满足以下条件的管理员：

- 用户角色为管理员。
- `comment_email_notifications_enabled = true`。
- 已配置非空、有效邮箱。

管理员收件人按规范化邮箱去重。规范化规则为去除首尾空白并转换为小写，避免同一邮箱因大小写不同收到多封邮件。

### 用户回复通知

仅当本次评论具有直接父评论时，才考虑发送用户回复通知：

- 收件人为直接父评论作者，不通知更上层评论作者或线程中的其他参与者。
- 父评论作者已开启评论邮件通知。
- 父评论作者已配置有效邮箱。
- 父评论作者与回复者不是同一用户。

### 合并与去重

管理员通知收件人与用户回复通知收件人合并后，按规范化邮箱去重：

- 同一邮箱最多收到一封邮件。
- 当某管理员同时也是被回复者时，保留管理员通知邮件，不再额外发送用户回复邮件。
- 回复者本人不会收到用户回复通知；如果回复者同时是管理员，仍可依据管理员规则收到管理员通知。

## 评论通知流程

评论创建流程保持数据库写入为主流程：

1. 校验用户、文章或留言板目标、父评论及评论内容。
2. 在现有流程中写入评论并返回完整评论数据。
3. 评论成功写入后，启动独立的尽力而为通知任务。
4. 通知任务查询目标标题、回复关系和符合条件的收件人。
5. 为去重后的每个收件人生成对应邮件并发送。
6. 单封邮件失败时记录服务端错误日志，继续发送其他邮件。

通知任务不阻塞评论接口响应。通知查询或邮件发送失败时，评论仍然发布成功，客户端不会收到评论发布失败错误。

本次功能不增加持久化任务队列和失败重试机制；服务重启等极端情况下允许邮件未发送。

## 通知服务边界

新增独立评论通知服务，职责包括：

- 根据评论目标解析文章标题或留言板名称。
- 使用评论作者的 `name` 作为展示名称；未填写 `name` 时回退到 `username`。
- 查询并筛选管理员和直接父评论作者。
- 规范化邮箱、合并收件人并去重。
- 生成管理员通知或用户回复通知内容。
- 调用现有 Resend 邮件发送能力，并隔离发送错误。

评论创建服务只负责在写入成功后触发通知，不直接包含模板、收件人筛选和邮件发送细节。

## 邮件内容与模板

新增评论通知邮件模板，复用现有 LeiBlog 邮件模板的布局、品牌标识、颜色、间距和按钮样式。所有用户生成内容必须先进行 HTML 转义。

展示名称规则：

- 优先使用用户姓名字段 `name`。
- `name` 为空时使用 `username`。
- 不单独处理昵称字段，昵称即姓名。

管理员邮件根据目标和行为显示：

- 文章评论：`张三在《文章标题》文章评论了：评论内容`
- 文章回复：`张三在《文章标题》文章回复了评论：回复内容`
- 留言板评论：`张三在留言板评论了：评论内容`
- 留言板回复：`张三在留言板回复了评论：回复内容`

用户回复邮件根据目标显示：

- 文章回复：`李四在《文章标题》文章中回复了你的评论：回复内容`
- 留言板回复：`李四在留言板中回复了你的评论：回复内容`

邮件主题应区分管理员通知和用户回复通知，并包含文章标题或“留言板”，便于收件人识别。

## 后台界面

在后台“管理员设置”页面：

- 将现有折叠项标题“偏好”改为“偏好设置”。
- 在该区域增加“评论邮件通知”开关。
- 说明文字明确该开关控制全站文章和留言板的新评论、新回复邮件。
- 开关保存成功后立即生效。
- 保存失败时恢复原状态并显示现有风格的错误提示。

界面沿用现有后台表单、折叠项和开关样式，不增加新的视觉体系。

## 前台个人中心

在前台个人中心：

- 新增“偏好设置”区域。
- 添加“评论回复邮件通知”开关。
- 说明文字明确该开关仅控制自己评论收到直接回复时的邮件。
- 开关保存成功后立即生效。
- 保存失败时恢复原状态并显示现有风格的错误提示。

界面沿用现有个人中心的布局、折叠项和响应式规则。

## 安全与错误处理

- 偏好接口只允许已登录用户修改自己的开关。
- 收件人邮箱不暴露给评论发布者或其他用户。
- 评论作者姓名、用户名、文章标题和评论内容在邮件 HTML 中转义。
- 邮件发送失败只写入服务端日志，不影响评论创建接口。
- 单个收件人发送失败不影响其他收件人。
- 无有效邮箱、关闭通知或自我回复的用户被跳过。
- 管理员与被回复者邮箱相同时只发送一封管理员通知邮件。

## 测试策略

### 服务端

- 迁移测试验证新字段存在、非空且默认开启。
- 当前用户资料测试验证返回评论邮件通知偏好。
- 偏好接口测试覆盖登录校验、布尔值校验和保存结果。
- 管理员筛选测试覆盖角色、开关状态、空邮箱和无效邮箱。
- 测试管理员邮箱大小写不同时仍能正确去重。
- 测试回复只通知直接父评论作者。
- 测试自我回复不发送用户回复通知。
- 测试管理员同时为被回复者时只发送管理员通知。
- 测试文章评论、文章回复、留言板评论和留言板回复的邮件内容。
- 测试姓名为空时回退到用户名。
- 测试邮件模板对用户生成内容进行 HTML 转义。
- 测试单封邮件失败不影响其他邮件发送。
- 测试通知任务失败不影响评论发布成功。

### 前端

- 测试后台“偏好”已改为“偏好设置”。
- 测试后台评论邮件通知开关加载、保存和失败恢复。
- 测试前台个人中心存在“偏好设置”区域。
- 测试前台评论回复邮件通知开关加载、保存和失败恢复。
- 测试管理员和普通用户首次加载时默认显示开启状态。

### 验证

- 运行数据库迁移、服务端测试和类型检查。
- 运行前端测试、类型检查和生产构建。
- 浏览器验证后台管理员设置和前台个人中心的桌面、移动布局。
- 使用测试邮箱验证文章评论、文章回复、留言板评论和留言板回复邮件。
- 临时模拟 Resend 发送失败，验证评论仍然发布成功。

## 验收标准

- 所有邮箱有效、开关开启的管理员会收到每条文章和留言板评论、回复通知。
- 管理员收件人按规范化邮箱去重。
- 普通用户在自己的评论收到直接回复时会收到邮件。
- 自我回复不会发送用户回复通知。
- 管理员与被回复者邮箱相同时只收到一封管理员通知邮件。
- 管理员和普通用户的通知开关默认开启，并可在各自偏好设置中关闭。
- 后台“偏好”已改为“偏好设置”。
- 邮件内容使用姓名，姓名为空时回退到用户名。
- 邮件模板沿用现有 LeiBlog 邮件视觉风格，并安全转义用户内容。
- 邮件发送失败不影响评论正常发布。
- 所有新增测试、现有测试、类型检查和构建通过。
